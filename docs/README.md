# Documentation

## What the audit examines

- [Scope](scope.md): the targets, the 14 workstreams, what is out, the authorization and the rules.
- [System model](system-model.md): the kernel's security-relevant parts, where each lives, and which of the project's pages describes it.
- [Threat model](threat-model.md): the five adversaries findings are ranked against.

## How it is done

- [Method](method.md): phases, evidence, refutation, dynamic testing.
- [Tools and pipeline](pipeline.md): what already runs in the project's CI, what the audit runs from the project's tree, and what it adds.
- [Claims](claims.md): the register, the verdicts and the tests behind behavioural claims.
- [Explainers](explainers.md): the plain-language account written for each mechanism.
- [AI assistance](ai-use.md): what the assistant does, what it never decides, where it runs.

## How results are handled

- [Severity](severity.md): the table findings are rated against.
- [Disclosure](disclosure.md): how a finding moves to publication, and how to report one.

## Where it stands

- [Status](status.md): what is done, what is not started, and the first measured result.
