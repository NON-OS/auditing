## Preconditions

- Ability to send OP_DECODE_JPEG to the image codec with a surface holding the file (whether an arbitrary capsule may reach the endpoint was not traced)

## Description

build_decode_tables runs 'let mut j = 1u8; while j <= t.bits[i] { ...; j += 1 }'. When bits[i] == 255 the condition is always true, so j overflows. parse_dht checks only that the total is at most 256 and that the bytes fit, so one class of 255 passes. With overflow checks the add panics; in a release profile (panic=abort, no overflow checks) j wraps, the output index passes 257 and the decoder panics with index out of bounds. The capsule's panic handler logs and exits with status 134.

## Impact

A crafted JPEG ends the image codec capsule. The codec is on init's supervisor watch list, so a restart is likely, but the restart policy was not read. Nothing in the kernel is affected. A second caller of parse_dht (coef/state/header.rs:33) was not exercised.

## Attack scenario

1. Build a JPEG: SOI, SOF0 8x8 one component, DHT class 0 id 0 with BITS[1]=255 and 255 zero values, EOI (294 bytes).
2. Send it with OP_DECODE_JPEG; decode_sized reaches the DHT after the header peek.
3. The decoder panics and the capsule exits.

## Evidence

Reproduced: yes.

- Found by a libFuzzer + ASAN round on the image decode target; hand-built to a 294-byte input. On the host fuzz harness the input panics at build_decode_tables.rs:28 (attempt to add with overflow); the control with BITS[1]=254 and 254 values does not crash. Reproduced twice.
- An independent check built the input from the description (byte-identical) and reproduced the same panic. It then called the real decode_sized in a release profile with panic=abort on stable rustc: the 255 input panicked at build_decode_tables.rs:26 with index out of bounds (len 257, index 257), exit 134; the 254 control returned Err(-90), exit 0.
- NOT done: no booted kernel, no run in the capsule's own embedded build, no IPC or surface path, no supervisor restart observed.

## Remediation

Reject bits[i] above the code space for length i in parse_dht, and loop with a wider counter or 'for _ in 0..bits[i]'.
