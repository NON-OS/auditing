## Preconditions

- Write access to the verification/lean tree (insider or supply-chain change)
- Corpus root is then bound to the attested image as if every load-bearing theorem used standard axioms only

## Description

The script extracts axiom names with grep -oE "'[^']+'" on #print axioms output, but only the theorem name is quoted ('Thm' depends on axioms: [A, B]). The extracted tokens are theorem names, all starting Nonos., and the filter that drops Nonos.|propext|Classical.choice|Quot.sound leaves nothing, so any axiom (also outside the Nonos namespace) passes. Only the sorry grep is effective. The CI gate fails only on sorryAx in axioms.txt, AxiomProfile.lean lists 651 of 1604 theorems, and the root hashes only verification/lean/Nonos, not verification/extraction or formal/.

## Impact

Process-assurance gap: the claim that the corpus root forms only over standard axioms is false at this commit. No runtime effect.

## Attack scenario

1. Contributor adds `axiom Evil : False` and a theorem using it to the Nonos namespace.
2. proof-corpus-root.sh exits 0 and prints a root.
3. The root is attested as covering proven properties.

## Evidence

Reproduced: yes.

- Reproduced twice, independently, with Lean 4.15.0: the probe output [Nonos.Evil] and [OutsideEvil] passes the script's pipeline, and the real script, run end to end on a copy with the injected axiom, exits 0 and prints a root.
- Not tested: main; whether another script commits a root over verification/extraction or formal/.

## Remediation

Parse the bracketed axiom list of each #print axioms line and compare to an exact allowlist, fail on any other axiom or on theorems missing from the profile, and make the escape-hatch grep a gate.
