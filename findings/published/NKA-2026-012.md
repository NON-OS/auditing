## Preconditions

- Secure Boot off or an attacker application signed for db, and a TPM that answers
- Attacker application first in boot order that LoadImage()s the genuine loader without starting it

## Description

replay keeps only the digest of the last EV_EFI_BOOT_SERVICES_APPLICATION in PCR 4; measured() treats it as the loader. A foreign application earlier in the log is not examined; the log only has to replay to live PCR 4. The project's own nsh document names this attack and the remote nsh verifier rejects it; the kernel's local verdict and its wording ('what ran last before the kernel') do not.

## Impact

The local MkBootAttest record, About screen and installer proofs panel can show 'measured and enrolled' for a boot where a foreign application ran first. No key effect: PCR 4 then includes the foreign application so PCR-bound keys do not open and a remote quote shows it. The attacker could equally patch the kernel's local report. Label accuracy only.

## Attack scenario

1. Attacker app X loads the genuine BOOTX64.EFI (firmware measures it) and does not start it.
2. X loads the genuine kernel and builds a handoff with the real log, trailer and record.
3. Kernel replay equals live PCR 4, last application is the enrolled loader: Verdict::Measured.

## Evidence

Reproduced: yes.

- Reproduced twice, independently, at the gate level: a test in a copy of nonos-boot-measure and nonos-attest-path (cargo test) printed Ok((true, 5)) for a foreign application measured before the enrolled loader.
- NOT run: no firmware; that EDK2/OVMF measures at LoadImage for an image never started is taken from the project's nsh document.

## Remediation

Apply the nsh PCR 4 rule in the kernel (every application event before the last must be an enrolled boot application or boot manager) or reword the verdict to say last application only. Regression test: foreign app before the loader gives refusal or a different verdict.
