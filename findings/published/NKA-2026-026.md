## Preconditions

- A make/cargo build that sets nonos-production and nonos-dev-attest without nonos-release

## Description

The compile_error in lib.rs guards only nonos-release + nonos-dev-attest. nonos-production does not imply nonos-release, so production + dev-attest compiles, while Cargo.toml and path.rs say production refuses it. With dev-attest the spawn gate takes a path-only trailer without a STARK proof (path.rs:64-66).

## Impact

A downstream or mistaken build can produce a kernel with the weaker capsule admission and no compiler refusal. On the nix path config.nix:236 and the loader's kernel signature check stop the pairing; those were not tested. Documentation/guard mismatch, no runtime attacker route.

## Attack scenario

1. A builder sets nonos-production,nonos-dev-attest.
2. cargo check passes; the kernel admits capsules on path alone.

## Evidence

Reproduced: yes.

- An independent check ran cargo check --no-default-features --features microkernel-core,nonos-production,nonos-dev-attest on b3dd1fa with a scratch signing seed in /tmp: exit 0 (Finished in 1m03s). Control with nonos-release,nonos-dev-attest: exit 101, error at src/lib.rs:45.
- NOT run: a full build, a boot, or the loader's behaviour with a path-only kernel.

## Remediation

Make lib.rs refuse nonos-dev-attest beside nonos-production unless a dev-only marker feature is present, or correct the three comments.
