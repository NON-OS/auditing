## Preconditions

- A path that installs a signal handler; none is reachable at this commit (SigState::set_action has no caller, no sigaction syscall)

## Description

read_callee_saved copies rbx,r12-r15 with mov, assuming they still hold user values; the hook's prologue has already pushed them and reused them. The asm file's own comment says Rust cannot read them. The captured Context is the one written into a user SigFrame when a handler is installed.

## Impact

No reachable effect: handler installation is unreachable, so the wrong values never reach a user stack. If a sigaction path is added, kernel loop values would be copied to user memory (register disclosure) and the user's values lost on return.

## Attack scenario

1. A future change makes set_action reachable.
2. A signal is delivered on syscall return; the frame holds kernel loop values.

## Evidence

Reproduced: yes.

- Disassembly (objdump -d -M intel) of syscall_return_signal_hook in two independent builds of b3dd1fa, a development build and a default-feature release build: capture is mov rcx,rbx; mov r8,r12; mov r9,r13; mov rsi,r14; mov rdx,r15 after those registers hold pid, constants, the pending mask and a loop counter.
- NOT shown: any route that installs a handler; nothing was booted to exercise the hook.

## Remediation

Take the callee-saved values from the frame saved at syscall.S:43-49 instead of reading live registers, or delete the unreachable install path.
