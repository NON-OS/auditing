## Preconditions

- A future caller of SeqLock

## Description

write stores an odd sequence with Release then does a plain data store, which may move above it; read copies the data non-atomically while a writer may run; write is a safe fn although writers must be serialised by the caller, and the type is Sync. No code outside the module uses it (the clock page has its own seqlock). Only the sequence arithmetic is covered by proofs.

## Impact

No effect today. A future caller could read a torn value, or race two writers from safe code.

## Attack scenario

1. A future caller of SeqLock

## Evidence

Reproduced: yes.

- Host harness including the unmodified seqlock files; cargo miri run (reader): Undefined Behavior, data race between non-atomic read and write; (two-writers): data race between two non-atomic writes. An independent check reproduced both reports.
- NOT done: No native torn-read demonstration on hardware.

## Remediation

Make write unsafe or lock internally; copy data with atomic or volatile loads; fence after the odd store.
